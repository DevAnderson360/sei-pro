# Pesquisar Link Permanente e Processos em Lote em TypeScript — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Reescrever os dois modais do menu lateral do SEI Pro (Pesquisar Link Permanente, Processos em Lote) em TypeScript, com as dez melhorias aprovadas e código comum no `sei-comum`.

**Architecture:** Dois pacotes novos (`link-permanente/`, `processos-lote/`) no molde do `historico/`: content script (mundo isolado) liga o evento do item do menu, abre um iframe com o app da extensão e atende pedidos de RPC (única parte com cookie do SEI); o app faz a UI e o laço. Controle de modal, executor de lote, extração de protocolos e tabela de resultado ficam no `sei-comum`.

**Tech Stack:** TypeScript 5.9, esbuild, tsx + linkedom (provas sem framework: `checar`/`secao`), biome. Aliases `@comum/*`, `@nucleo/*`.

**Spec:** `docs/superpowers/specs/2026-10-16-lote-ts-design.md`

## Global Constraints

- Entrega só em `dist/manifest.json` (Lab MV3). Não mexer nos outros manifests nem remover o código legado.
- JS gerado em `dist/` só com ASCII (esbuild `charset: "ascii"` + portão de bytes no `build.mjs`, como `historico/build.mjs`). Arquivos gerados levam o banner "GERADO por ... NAO EDITE".
- Edições em `dist/js/*.js` legados: acentos como `\uXXXX`; conferir por bytes, não por grep (memória `feedback_sei_unicode_escape`). Não commitar `dist/js/sei-functions-pro.js` e `dist/js/sei-pro-docs-lote.js` que estejam sujos de outra sessão: usar `git add` por arquivo.
- DOM seguro: `h()` de `@comum/ui/dom`, nunca `innerHTML`. Modal sem botão Cancelar (X e Esc fecham). Textos em português do Brasil, tokens `--spro-*`, tema claro e escuro.
- Link gerado: `controlador.php?acao=procedimento_trabalhar&id_procedimento=N[&id_documento=M]` sem `infra_hash`.
- Lote: pausa padrão 500 ms (mín. 200, máx. 10000), teto 2000 processos, 900 ms por requisição na estimativa, troca de caracteres para latin-1 como `PROCLOTE_TROCAS` de `dist/js/sei-pro-proc-lote.js:41-52`, limite de 100 caracteres na especificação, `rdoNivelAcesso` 0/1/2, hipótese `value="null"` descartada.
- Todo trabalho na worktree `../sei-pro-lote` (branch `feat/lote-ts`). Cada pacote precisa de `npm install` próprio (sem `node_modules` na worktree).

- Sessão expirada no meio da rodada: linha vira erro com mensagem, lote pausa em vez de queimar a fila (Tasks 2 e 10).

### Task 2: Executor de lote e ritmo adaptativo

**Files:**
- Create: `sei-comum/src/lote/executor.ts`

**Interfaces:**
- Produces:
```ts
export type Situacao = "pendente" | "ok" | "nao-encontrado" | "sem-acesso" | "erro" | "pulado";
export interface ItemLote<E, R> { indice: number; entrada: E; situacao: Situacao; resultado?: R; erro?: string; tentativas: number }
export interface SaidaItem<R> { situacao: Exclude<Situacao, "pendente" | "pulado">; resultado?: R; erro?: string; parar?: boolean }
export interface OpcoesExecutor<E, R> {
  concorrencia: number;                       // 1 = em sequência
  pausaMs(): number;                          // lida a cada despacho (ritmo adaptativo)
  processar(entrada: E, indice: number): Promise<SaidaItem<R>>;
  aoMudar?(item: ItemLote<E, R>): void;
  esperar?(ms: number): Promise<void>;        // injetável nas provas
}
export type EstadoLote = "ocioso" | "rodando" | "pausado" | "cancelado" | "concluido";
export class ExecutorLote<E, R> {
  constructor(itens: ItemLote<E, R>[], o: OpcoesExecutor<E, R>);
  readonly estado: EstadoLote;
  readonly progresso: { feitos: number; total: number; falhas: number };
  iniciar(): Promise<void>;        // resolve ao concluir, pausar ou cancelar
  pausar(): void; continuar(): Promise<void>; cancelar(): void;
  repetirFalhas(): Promise<void>;  // reprocessa itens "erro" (não "nao-encontrado")
}
export class RitmoAdaptativo {
  constructor(base: number, teto?: number);   // teto padrão 10000
  registrar(duracaoMs: number): void;
  pausaMs(): number;
}
```

- [ ] **Step 1: Provas (falham).** (a) com `concorrencia: 3` e 7 itens, nunca mais de 3 `processar` simultâneos e a ordem de despacho é a dos índices; (b) `cancelar()` com 2 em voo: os 2 terminam e viram `ok`, o resto fica `pendente`, estado `cancelado`; (c) `pausar()`/`continuar()` retomam sem repetir item `ok`; (d) uma saída com `parar: true` pausa o lote depois de registrar o item; (e) `repetirFalhas()` reprocessa só `erro`, incrementa `tentativas`; (f) exceção lançada por `processar` vira `erro` com a mensagem, o lote segue; (g) `RitmoAdaptativo(500)`: 5 durações de 600 ms fixam a linha de base; depois duas de 1400 ms sobem a pausa para ≥ 1000 e nunca passam do teto; durações de volta a 650 ms trazem a pausa de volta a 500.
- [ ] **Step 2:** Rodar; Expected: FALHA.
- [ ] **Step 3:** Implementar. Despacho com pool de `concorrencia` trabalhadores; entre despachos do mesmo trabalhador, `await esperar(pausaMs())`. `RitmoAdaptativo`: linha de base = média das 5 primeiras; média móvel das últimas 3; ≥ 2× a base → pausa dobra (até o teto); < 1,5× → volta à base.
- [ ] **Step 4:** Rodar; Expected: PASS.
